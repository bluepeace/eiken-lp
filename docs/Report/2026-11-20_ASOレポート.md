# AiKen ASOレポート（2026-11-20）

App Store の iOS アプリ「AiKen｜英検単語・4技能対策」について、アプリのダウンロードを増やすために何を直すかを整理した。Google Play は公開（11/2）から日が浅いので、今回は扱わない。

まず結論。

1. **詰まっているのは、検索結果からプロダクトページへ進むところ。** インプレッション6,410に対してページ閲覧は445（約7%）。一方で、ページを見た人のうち約34%（152件）がダウンロードしている。手を入れる順は、検索結果に出る部分（名前、サブタイトル、アイコン、スクリーンショットの1〜3枚目）が先で、説明文は後。
2. **キーワード欄の約30文字が、名前・サブタイトルと重なって無駄になっている。** 級の名前と面接はすでに入っている。級の前の「英検」、サブタイトルにある「AI」「英作文」「5級」「1級」を外し、「勉強」「要約」「単語帳」「中学生」などに入れ替える（§3）。
3. **第3回（申込締切 12/14、一次 2027-01-24）の前に、宣伝テキストとアプリ内イベントを使う。** どちらも検索結果やページで目に入る場所で、宣伝テキストは審査なしで差し替えられる。
4. **流入元を分けて見られるようにする。** LP からストアへのリンクにキャンペーン用のパラメータ（`pt` / `ct`）を付け、App Store の検索から来た人と aiken.life から来た人を分けて数える。

- 発音：スピーキングの練習
- 中学生、小学生：受験者層。保護者が探すときの語

外したままの語：他社のアプリ名と「英検®」。他社名は審査で外される。

名前に「面接」を足し、「英検対策」を一続きにする。「面接」はキーワード欄にもあるが、名前に入れたほうが検索での重みが大きい。競合も「面接対策」「面接の練習」を名前に入れている。名前に「面接」を入れたら、キーワード欄からは外して、空いた3文字をほかの語に使う。級の名前は名前に入れると長くなり、検索結果で読みにくくなるので、キーワード欄に残す。

## 4. 施策

### A. 今週やること（App Store Connect、審査なしか軽い審査）

| 順 | 作業 | 理由 |
|----|------|------|
| 1 | キーワード欄を §3 の案に差し替える | 名前・サブタイトルと重なる約30文字を、まだ拾えていない語に使う |
| 2 | プロモーション用テキストを第3回向けにする（文案と手順は下） | 審査なしで差し替えられる。申込締切 12/14 の前に出す |
| 3 | スクリーンショットの1〜3枚目に、級を選べること・AI採点の面接・AI添削を、短い文字で出す | 検索結果に出るのは最初の数枚。タップ率（6.9%）を上げる |
| 4 | [ストア公開.md](../ストア公開.md) の名前・サブタイトル・言語を今の値に直す　**済（11/20）** | LP と FAQ はこの文書を正としているため |

#### プロモーション用テキスト

プロダクトページの説明文のいちばん上に出る、170文字までの文。審査に出さずに、いつでも差し替えられる。検索のキーワードとしては使われないので、試験の時期に合わせた案内を書く場所として使う。

手順：App Store Connect → AiKen → 左の「iOS App」の配信中のバージョン（1.2.4）→「プロモーション用テキスト」を書き換えて「保存」。数時間ほどでストアに反映される。

文案（108文字）。

```
第3回英検（一次試験1月24日）に向けて、今日から対策。単語と文法は毎日無料、リーディング・リスニング・ライティング・スピーキングは最初の5日間使い放題。ライティングはAIが添削し、面接の受け答えもAIが採点します。
```

差し替える前の文（2026-11-20 時点）。試験の時期が過ぎたら、この文に戻すか、これをもとに書き直す。

```
英検5級〜1級に、これ1つで対応。文法を追加し、5級から2級まで無料で学べます。
単語と4技能は、AIの採点・添削つき。1回5〜10分のすきま時間で、毎日続けられます。
```

一次試験のあと（1/25以降）は、二次試験（2/28・3/7）向けの文に替える。

#### 実装済み：LP → ストアの計測（11/20）

12月まで待つ理由がないので前倒しした。LP のストアへのリンクは、すべて `config.php` の `lp_app_store_url()` / `lp_play_store_url()` を通る（ストア導線の部品 `store-cta.php`、フッター、塾・学校・メディア向けページ）。

- キャンペーン名は `lp_{ページ}_{級}_{位置}`。例：`lp_top_hero`、`lp_grade_3kyu`、`lp_speaking_2kyu_footer`。登録リンクの pid と同じ考え方。
- App Store：`?pt=<プロバイダトークン>&ct=<キャンペーン名>&mt=8`。App Store Connect のアナリティクスで「キャンペーン」ごとのインプレッション・ダウンロードが見える。**`APP_STORE_PROVIDER_TOKEN` が空のあいだは付けない**（ct だけでは計測されない）。
- Google Play：`&referrer=utm_source=aiken.life&utm_medium=lp&utm_campaign=<キャンペーン名>`（URLエンコード）。Play Console の「ユーザー獲得」でキャンペーン別に見える。
- 構造化データ（`sameAs`）のストアURLは、パラメータなしのまま。

### B. 12月にやること

- **アプリ内イベント**：「第3回 一次試験 直前対策」のようなイベントを 12/14 前後から 1/24 まで出す。検索結果とページにカードで出て、インプレッションが増える。
- **LP → ストアの計測**：11/20 に前倒しで実装した（§4A の後ろの「実装済み」を参照）。
- **カスタムプロダクトページ**：級別LP（`/3kyu/` など）から、その級のスクリーンショットを先頭にしたページへ送る。キーワードとの紐づけもできる。閲覧が少ないうちは、3級と準1級の2つから始める（Web検索で需要が見えている級）。

### C. やらないこと（今期）

- **プロダクトページの最適化（A/Bテスト）**：閲覧が90日で445しかなく、結果が出るまで時間がかかりすぎる。カスタムプロダクトページとキーワードを先にやる。
- **説明文の書き直し**：ページに来た人の34%がダウンロードしている。説明文は詰まっている場所ではない。
- **カテゴリの変更**：教育のままにする。
- **評価の依頼の追加**：アプリにはすでに、良い結果のときと連続学習の節目に OS の評価シートを出す仕組みがある（`eiken-app/mobile/lib/store-review-prompt.ts`）。評価4件は、母数が小さいことの結果。
